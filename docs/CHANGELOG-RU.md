# Что нового в нашем форке

Здесь — только то, что отличает наш форк (`StApZzZ/hermes-agent`) от оригинального Hermes, и когда мы
забирали обновления из оригинала. Изменения самого Hermes — в его репозитории
[NousResearch/hermes-agent](https://github.com/NousResearch/hermes-agent).

**Версии** — по дате выпуска: `2026.11.08`, второй выпуск за день — `2026.11.08.2`. Свою версию
показывает `hermes --version`: `… · fork 2026.11.08`. Если после выпуска есть ещё коммиты, к версии
добавляется их число: `fork 2026.11.08+3`. В git версии — теги `fork-2026.11.08`.

**Выпустить версию** (на чистом `main`, совпадающем с `origin/main`): дописать раздел «Не выпущено»
ниже, затем

```bash
python scripts/fork_release.py                  # проверить и посмотреть
python scripts/fork_release.py --apply --push   # выпустить и опубликовать
```

После этого на сервере — `hermes update`.

## Не выпущено

## 2026.11.14

### Новое

- **Бот рассказывает о себе при первом сообщении.** На `/start` — то, что Telegram отправляет сам,
  когда человек впервые открывает бота, — раньше приходила пустота: первое знакомство со своим же
  агентом было молчанием. Теперь приходит короткий рассказ: что он умеет именно здесь, работают ли
  голосовые и где посмотреть команды. Список возможностей собирается из инструментов, реально
  включённых для этой платформы, поэтому пообещать то, чего не умеет, бот не может.
- **Распознавание речи настраивается одной командой.** `hermes setup stt` показывает все размеры
  модели Whisper — сколько скачивать, сколько займёт памяти, насколько хорошо слышит и как быстро, —
  советует подходящий вашему серверу, спрашивает язык, ставит faster-whisper, заранее скачивает
  модель (чтобы первое голосовое не ждало) и предлагает перезапустить бота. Облачные провайдеры
  по-прежнему в `hermes tools` → Speech-to-Text.
- **Первая настройка спрашивает про голосовые.** Быстрая настройка — режим по умолчанию — не
  доходила до шага инструментов, и бот получался такой, что голосовые принимает, а расслышать не
  может. Теперь, если подключён мессенджер, расшифровка предлагается сразу, а для локального Whisper
  настройка доводится до конца — модель и язык, без «запустите ещё одну команду».
- **`hermes doctor` замечает две немые поломки.** Раздел **Speech-to-Text** говорит, работает ли
  расшифровка, и чем лечить, если нет: без провайдера агенту вместо ваших слов приходит заглушка, он
  отвечает на то, чего не слышал, и в чате об этом нет ни слова. Раздел **Messaging Polling** ловит
  второй запущенный гейтвей с тем же токеном бота: два поллера выбивают друг друга, и при каждом
  восстановлении Telegram **стирает очередь сообщений** — они не задерживаются, а пропадают совсем.

### Изменено

- **Выгрузка диагностики в Nous больше не включена по умолчанию.** `hermes debug share --nous` и
  кнопка «Send diagnostics» в десктопном приложении отправляют отчёт — а в нём логи, то есть
  содержимое переписки — в хранилище Nous. Теперь этот путь закрыт, пока вы сами его не откроете:

  ```bash
  hermes config set telemetry.nous_diagnostics true
  ```

  Запрет стоит на самом исходящем запросе, поэтому закрыты сразу все входы — консоль, гейтвей и
  кнопка в приложении. Пока выключено, отказ прямо называет эту настройку, а не выглядит поломкой.
  Подтверждение перед каждой отправкой осталось как было. Отчёт без выгрузки, как и раньше:
  `hermes debug share --local`.

## 2026.11.11.2

### Изменено

- **`web-access.sh` работает через Angie вместо Caddy.** Angie ставится из своего репозитория и сам
  получает сертификат Let's Encrypt (TLS-ALPN на 443, порт 80 остаётся закрытым). Сайт — отдельный файл
  `/etc/angie/http.d/hermes-web-access.conf`, `remove` удаляет только его.

## 2026.11.11

### Новое

- **Веб-панель по HTTPS, вход только из VPN.** `scripts/remote-dev/web-access.sh apply` (от root на сервере)
  открывает Webapp на `https://<домен>/` и веб-панель на `https://<домен>/panel/` через Caddy с сертификатом
  Let's Encrypt. Вход по паролю работает только с адресов из `dashboard.auth_networks` (по умолчанию — адреса
  VPN из allowlist SSH); с других адресов форма пароля не показывается, а открытая сессия не работает.
- **Hermes как приложение внутри Telegram.** Кнопка «Hermes» в меню бота открывает Webapp как Telegram Mini App
  и входит без пароля. Пускает только аккаунты из `dashboard.telegram_mini_app.allowed_users`; подпись Telegram
  проверяется токеном бота. Подробности — [REMOTE-DEVELOPMENT-RU.md](REMOTE-DEVELOPMENT-RU.md), раздел 8.

## 2026.11.10.2

### Новое

- **Рисование картинок по подписке ChatGPT.** Новый способ `codex-cli` для инструмента `image_generate`:
  картинку рисует сам Codex CLI, ключ API не нужен, вход остаётся внутри Codex CLI. Попросите бота
  «нарисуй …» — пришлёт картинку примерно через 30–60 секунд. Умеет и правки по присланному фото.
- **`/settings` → «🎨 Рисование».** Выбор, кто рисует картинки (из доступных на сервере); действует с
  нового разговора (`/new`). Пункт распознавания теперь называется «🖼 Распознавание».
- **«Нарисовать картинку» в веб-панели.** На странице «Изображения»: выбор, кто рисует, описание,
  формат (горизонтально / квадрат / вертикально) и кнопка «Нарисовать»; готовую картинку можно скачать.

## 2026.11.10

### Новое

- **Картинки работают с подписками Claude и Codex.** При провайдере `claude-cli` или `codex-cli` фото
  из Telegram и других чатов раньше не распознавались: подписочный клиент принимал только текст.
  Теперь изображение уходит в сам CLI (Claude — блоком картинки, Codex — файлом `--image`), и бот
  отвечает по содержимому фото. `gemini-cli` картинки по-прежнему не принимает и прямо об этом говорит.
- **Навык `image-recognition`.** Точный текст с фото и скриншотов (tesseract), QR- и штрихкоды
  (zbarimg), камера, время и GPS из EXIF (exiftool) и описание картинки через `claude`/`codex`.
  `python3 …/image_tools.py doctor` покажет, каких программ не хватает и как их поставить.
- **`/settings` в Telegram — настройки кнопками.** Одно меню: модель, рассуждение, быстрый режим,
  изображения, голос, личность, подтверждения, статус; каждая кнопка открывает свой выбор. Новое в нём —
  режим распознавания картинок (Авто / Напрямую / Описание), раньше его можно было сменить только в
  `config.yaml`. В других мессенджерах `/settings` присылает тот же список текстом.
- **Страница «Изображения» в веб-панели.** Режим распознавания, какая модель сейчас описывает
  картинки, какие программы распознавания установлены (с командой установки), и проверка на любой
  картинке: перетащите или вставьте её и получите описание, текст, коды и EXIF.

## 2026.11.08

### Новое

- **Версии форка и этот журнал.** `hermes --version` и заголовок `hermes` показывают версию форка.
- **`hermes repos` — инструменты из своих репозиториев.** Находит в соседних проектах MCP-серверы,
  скиллы и консольные утилиты и подключает их к Hermes. Где и что искать — аргументами
  (`hermes repos scan ~/mcp-repos --only maps-parser --kind mcp`). Скиллы проекта теперь читаются и
  из `.claude/skills`.
- **`hermes sync` — один Hermes на ПК и на сервере.** Настройки, память, скиллы и пространства
  синхронизируются в обе стороны по таймеру. Другие агенты (профили) переезжают, только если
  перечислены в `sync.profiles`.
- **Установка одной командой** (`scripts/deploy/hermes-deploy.sh`, `.ps1` для Windows) на сервер, в
  WSL или локально; `--lock` закрывает сервер для всех, кроме SSH по ключу с ваших адресов (Debian,
  Ubuntu, RHEL-подобные). Ежедневные копии сервера на ПК.
- **Пространства и общая память.** `hermes space` — работа, личное, проекты; `hermes memory` —
  общая память и перенос памяти между агентами.
- **Подписки вместо API-ключей.** Hermes думает через подписки Claude, ChatGPT (Codex) и Gemini.
- **Работа на сервере из VS Code** (`hermes remote`, Remote-SSH, долгие сессии в tmux).
- **Приватность.** Без статистики для разработчика, без гостевых аккаунтов Nous и без повторов
  веб-поиска через сторонние сервисы — пока вы сами это не включите.

### Исправлено

- `hermes sync` больше не может упасть на русских записях памяти под Windows.
- Профиль, убранный из `sync.profiles`, нигде не удаляется — даже если на сервере старый Hermes.
- Скрипты установки снова запускаются из клона без `chmod +x`.
