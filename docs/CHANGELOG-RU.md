# Что нового в нашем форке

Здесь — только то, что отличает наш форк (`StApZzZ/hermes-agent`) от оригинального Hermes, и когда мы
забирали обновления из оригинала. Изменения самого Hermes — в его репозитории
[NousResearch/hermes-agent](https://github.com/NousResearch/hermes-agent).

**Версии** — по дате выпуска: `2026.11.08`, второй выпуск за день — `2026.11.08.2`. Свою версию
показывает `hermes --version`: `… · fork 2026.11.08`. Если после выпуска есть ещё коммиты, к версии
добавляется их число: `fork 2026.11.08+3`. В git версии — теги `fork-2026.11.08`.

**Выпустить версию** (на чистом `main`, совпадающем с `origin/main`): дописать раздел «Не выпущено»
ниже, затем

```bash
python scripts/fork_release.py                  # проверить и посмотреть
python scripts/fork_release.py --apply --push   # выпустить и опубликовать
```

После этого на сервере — `hermes update`.

## Не выпущено

### Новое

- **Версии форка и этот журнал.** `hermes --version` и заголовок `hermes` показывают версию форка.
- **`hermes repos` — инструменты из своих репозиториев.** Находит в соседних проектах MCP-серверы,
  скиллы и консольные утилиты и подключает их к Hermes. Где и что искать — аргументами
  (`hermes repos scan ~/mcp-repos --only maps-parser --kind mcp`). Скиллы проекта теперь читаются и
  из `.claude/skills`.
- **`hermes sync` — один Hermes на ПК и на сервере.** Настройки, память, скиллы и пространства
  синхронизируются в обе стороны по таймеру. Другие агенты (профили) переезжают, только если
  перечислены в `sync.profiles`.
- **Установка одной командой** (`scripts/deploy/hermes-deploy.sh`, `.ps1` для Windows) на сервер, в
  WSL или локально; `--lock` закрывает сервер для всех, кроме SSH по ключу с ваших адресов (Debian,
  Ubuntu, RHEL-подобные). Ежедневные копии сервера на ПК.
- **Пространства и общая память.** `hermes space` — работа, личное, проекты; `hermes memory` —
  общая память и перенос памяти между агентами.
- **Подписки вместо API-ключей.** Hermes думает через подписки Claude, ChatGPT (Codex) и Gemini.
- **Работа на сервере из VS Code** (`hermes remote`, Remote-SSH, долгие сессии в tmux).
- **Приватность.** Без статистики для разработчика, без гостевых аккаунтов Nous и без повторов
  веб-поиска через сторонние сервисы — пока вы сами это не включите.

### Исправлено

- `hermes sync` больше не может упасть на русских записях памяти под Windows.
- Профиль, убранный из `sync.profiles`, нигде не удаляется — даже если на сервере старый Hermes.
- Скрипты установки снова запускаются из клона без `chmod +x`.
